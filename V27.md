# FibroBot V27 — Fiabilité du compagnon, fonctionnalités progressives

**Portée :** huit axes améliorés dans la PWA expérimentale existante. Une fonctionnalité intégrée au code n'est pas une validation clinique ni une garantie sur un appareil physique.

| Axe | Fonctionnalité intégrée | Limite réelle |
| --- | --- | --- |
| 1. Voix | Indicateur « écoute/parle », lecture segmentée et dictée avec option de proposition d'envoi après confirmation du texte | Pas de mot d'activation permanent ; dépendance aux capacités voix du navigateur ; double consentement distinct si IA distante |
| 2. Intelligence | Conservation du routeur Agnes → Mistral et des confirmations de transmission ; diagnostics supplémentaires de capacités réelles | Clés, quotas et CORS restent à vérifier avec de vraies API ; aucune promesse d'IA disponible sans clé |
| 3. Actions | Navigation déterministe vers les pages FibroBot ; liens externes allowlistés, notamment WhatsApp, Gmail, Agenda, Maps, YouTube et Facebook | Aucune ouverture automatique, aucun pilotage natif d'Android/iOS ou d'applications tierces |
| 4. Soins | Bilan coordonné enrichi de trois observations datées effectivement saisies ; aucune causalité inférée | Pas de diagnostic, prescription, calcul de dose ni validation clinique |
| 5. Rappels | Jusqu'à 8 horaires quotidiens **déclarés** par traitement, confirmations individuelles, compatibilité des anciens journaux ; export .ics récurrent générique volontaire | Ne déduit jamais une fréquence de prescription ; les alarmes PWA hors application ne sont pas garanties et l'import .ics doit être fait manuellement |
| 6. Lecture | Reprise au signet correspondant au même fichier TXT, MD, EPUB ou DOCX, stocké dans le coffre chiffré | Le contenu et la voix ne sont pas sauvegardés ; le fichier doit être choisi à nouveau ; PDF toujours en aperçu sans extraction |
| 7. Sécurité | Confirmation avant export calendrier et impression non chiffrée ; noms, doses et dossiers absents de l'ICS ; nouveaux tests de sécurité et compatibilité | Un calendrier externe voit les heures d'événements, les sauvegardes anciennes peuvent subsister, l'app n'est pas certifiée |
| 8. Interface | Raccourcis utiles, statut vocal accessible, aides aux horaires, boutons de signet, indicateur discret de lecture et respect de « animations réduites » | Compatibilité tactile et vocale encore à valider sur matériels réels |

## Vérification

Exécuter depuis la racine :

```sh
node --test tests/*.test.mjs
node --check app.mjs
node --check core.mjs
node --check medication-calendar.mjs
node --check local-commands.mjs
node --check reader-bookmark.mjs
```

Pour vérifier la PWA, utiliser le workflow GitHub Actions de navigateur sur la PR, puis inspecter sur **un Android Chrome réel et un iPhone Safari réel** les autorisations microphone, IndexedDB, sauvegarde/restauration, export ICS, réouverture hors ligne et navigation au clavier. Aucun test automatisé en Linux n'est équivalent à ces essais.

**Contrôles de sécurité conservés :** le verrouillage du coffre, l'accord par question pour Agnes/Mistral, la détection d'urgence et le refus des demandes de dosage ne doivent pas être contournés par les commandes de navigation. Le partage à des fournisseurs externes reste explicite et conditionné au contenu non médical admissible.

**Pour une future application native :** demander les permissions système adaptées et implémenter séparément les notifications locales fiables, l'intégration d'applications via intents Android / mécanismes iOS autorisés et, si possible, une écoute vocale à activation. Ces fonctions ne sont pas présentées comme disponibles dans la PWA V27.
